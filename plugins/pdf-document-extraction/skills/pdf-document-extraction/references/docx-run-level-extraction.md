# Docx Run-Level Extraction — When `para.text` Lies

## The trap

You call `doc.paragraphs[N].text` to get the text of a docx paragraph and get a flat string back. You parse it with regex. It works for prose paragraphs. It silently breaks for **structured content where term and body are in separate runs of the same paragraph**.

Real example from the target platform Sep 10, 2026 — education flashcard docx:

```
Doc looks like (Word's view):
  1.  What is Forex?
      The global market where currencies are traded against each other.

But para.text returns:
  "What is Forex? The global market where currencies are traded against each other."

And pandoc -t plain returns the same flat string PLUS
auto-generated numbering:
  "1.  What is Forex? The global market..."
```

Three things go wrong simultaneously:

1. **Word's list numbering is metadata, not run text.** The `1.  ` prefix appears in pandoc/pypandoc output but NOT in `python-docx`'s `para.runs[N].text` — it's in `para._element.find('.//{...}numPr')`. If your parser expects the number, you don't get it from python-docx. You have to either trust pandoc (which gives you the number) or maintain your own sequential counter.
2. **Soft line breaks inside one paragraph are preserved as separate runs.** The docx has the term and body on what looks like two lines in Word, but they're really two `<w:r>` runs in the same `<w:p>`. `para.text` joins them with no separator. You can't tell where the term ends and the body begins.
3. **Flat-text regex heuristics are fragile.** Trying to split "What is Forex? The global market..." on `. ` gives you "What is Forex" / "The global market...", but for "11.  Candlestick body Distance between open and close. Large body = strong conviction" the first period is in the body, not the term. The regex finds the wrong split.

## The fix — inspect `para.runs` directly

`python-docx` exposes the run structure. For the docx above, every card is exactly two runs:

```
Run 0: 'What is Forex? '    (term, with trailing space)
Run 1: 'The global market where currencies are traded against each other.'  (body)
```

The cleanest pattern:

```python
from docx import Document
doc = Document('/path/to/file.docx')

for para in doc.paragraphs:
    runs = [r.text for r in para.runs if r.text]
    if not runs:
        continue
    first_run = runs[0].strip()
    # ... check this paragraph is the kind you care about ...
    # (e.g. matches your card pattern: short noun phrase in run 0)
    if not looks_like_my_pattern(first_run):
        continue
    term = first_run  # already the term
    body = ' '.join(r.strip() for r in runs[1:] if r.strip())
```

The same pattern adapts to any structured docx where you have:
- A **first run** that holds the structured "header" (term, title, question, label)
- One or more **subsequent runs** that hold the body / answer / explanation
- A paragraph type that you can identify by the shape of run 0 (e.g. starts with uppercase, no period, short)

## Detect run-boundary hints first

Don't guess at the structure from a sample. Open the actual docx in a Python REPL first:

```python
from docx import Document
doc = Document('/path/to/file.docx')
for i, para in enumerate(doc.paragraphs[:30]):
    text = para.text
    runs = para.runs
    print(f'{i:3d}: text={text[:60]!r}, runs={len(runs)}')
    for j, run in enumerate(runs):
        print(f'      R{j}: {run.text!r}')
```

**Why this is the FIRST step:** The structure varies wildly by doc author. Some docs have everything in one run. Some have the number in run 0, some don't. Some have term + body in 2 runs, some have title + subtitle + body in 3 runs. Inspect first, then write the parser.

## When the list number IS in the run text

If pandoc/pypandoc preserves the numbering (it usually does, since pandoc converts `numPr` to ordered list prefixes), use pandoc for the parse and skip python-docx entirely:

```python
import subprocess
result = subprocess.run(
    ['pandoc', '/path/to/file.docx', '-t', 'plain'],
    capture_output=True, text=True, check=True,
)
text = result.stdout
# Now the text has "1.  What is Forex?..." with the number prefix
```

This is faster to write but loses the run-boundary info. Use it when:
- The doc was generated by pandoc-friendly authoring (Word native, Google Docs export)
- You need the list numbers for sequencing
- The structure is "term and body in one paragraph, separated by period+space" and the period+space happens to land on a clean term boundary

## When the list number is NOT in the run text (Word's metadata-only numbering)

This is the case where you must use python-docx. The number is in `<w:numPr>` not in the run text. Maintain your own sequential counter:

```python
current_module = None
current_set = None
card_counter = 0
quiz_counter = 0

for para in doc.paragraphs:
    text = para.text.strip()
    if not text:
        continue

    # Detect section boundaries by content shape, not by number
    m = re.match(r'^Module (\d+) – (.+)$', text)
    if m:
        current_module = {'number': int(m.group(1)), ...}
        card_counter = 0
        continue

    m = re.match(r'^Flashcard Set ([ABC])$', text)
    if m:
        current_set = {'letter': m.group(1), ...}
        card_counter = 0
        continue

    # Card: 2 runs, run 0 = term, run 1+ = body
    runs = [r.text for r in para.runs if r.text]
    if not runs or not current_set:
        continue
    first_run = runs[0].strip()
    if not first_run:
        continue
    card_counter += 1
    term = first_run
    body = ' '.join(r.strip() for r in runs[1:] if r.strip())
    # ... record (card_counter, term, body)
```

The `card_counter` resets at every Set header. The `current_module.number` resets at every Track header (modules are per-track, not global). If you need globally-unique slugs, derive them from the module slug, not the module number:

```python
mod_slug_prefix = current_module['slug'][:24]
set_slug = f"{mod_slug_prefix}-set-{current_set['letter'].lower()}"
```

Otherwise two modules in different tracks that happen to be numbered "Module 1, Set A" collide.

## When questions use `→` separators

Many quiz-style docx files have a single-line format:

```
1.  True or False: EUR/USD is a major pair.  → True
2.  What does GBP/USD = 1.3100 mean?  → 1 British Pound buys 1.3100 US Dollars
```

Pandoc preserves this flat — the question number, prompt, and answer all on one line. Parse with:

```python
m = re.match(r'^(.+?)\s+→\s+(.+)$', text)
if m:
    prompt = m.group(1).strip()
    answer = m.group(2).strip()
    # The leading "N.  " may or may not be present depending on numbering
```

The number prefix may be present in pandoc output but absent in python-docx output. Use a regex that doesn't require the number:

```python
m = re.match(r'^(.+?)\s+→\s+(.+)$', text)
# Works whether or not the leading "1.  " is there
```

**True/False detection:** if the answer is exactly "True" or "False" (case-insensitive), treat it as a truefalse question. Otherwise it's a free-text / mcq answer.

## When soft line breaks flatten to single lines

`pandoc -t plain` collapses soft line breaks (Shift+Enter in Word) into single spaces. If the original docx has a card with the term on line 1 and the body wrapping onto lines 2-3, pandoc gives you:

```
1.  What is Forex? The global market where currencies are traded against
each other. Largest financial market in the world.
```

Single line, but with `\n` characters preserved only at HARD breaks. The semantic structure (term ends after "Forex?", body starts at "The global market") is invisible. **The fix:** open the docx directly with python-docx and read `para.runs` — soft breaks become separate runs.

## Detection recipe: which tool to use

| Symptom in the docx | Use this tool |
|---|---|
| Numbers visible, soft breaks collapsed, paragraph structure preserved | `pandoc -t plain` (fast, regex on text) |
| Numbers NOT visible, soft breaks matter, structured content | `python-docx` + `para.runs` (slower, but preserves boundaries) |
| Mixed — some sections numbered, some not, runs split for some paragraphs | `python-docx` everywhere; add the number yourself |
| Doc has tables, images, headers, footers | `python-docx` — pandoc flattens tables inconsistently |
| Doc has tracked changes / comments / revisions | `python-docx` — pandoc has limited support |

## Verifying the parse

After building the parser, dump the first 10 parsed records to confirm term/body boundaries look right:

```python
for module in modules[:2]:
    for set_obj in module['sets'][:1]:
        for card in set_obj['cards'][:5]:
            print(f"  Card {card['number']}: term={card['term'][:50]!r}")
            print(f"           back={card['back'][:60]!r}")
```

If a term looks too long (e.g. "Candlestick body Distance between open and close" instead of just "Candlestick body"), the run split is wrong. If the back is empty or truncated, the `runs[1:]` slicing is wrong. **Verify the run structure with the inspection snippet above before debugging the parser.**

## Real example end-to-end

```python
from docx import Document
import re

def slugify(text):
    text = re.sub(r'[^a-zA-Z0-9\s-]', '', text.lower())
    return re.sub(r'\s+', '-', text).strip('-')

doc = Document('/path/to/education-flashcards.docx')

modules = []
current_module = None
current_set = None
current_quiz = None
card_counter = 0

for para in doc.paragraphs:
    text = para.text.strip()
    if not text:
        continue

    m = re.match(r'^Module (\d+) – (.+)$', text)
    if m:
        current_module = {
            'number': int(m.group(1)),
            'title': m.group(2).strip(),
            'slug': slugify(m.group(2)),
            'sets': [],
            'quizzes': [],
        }
        modules.append(current_module)
        current_set = None
        current_quiz = None
        card_counter = 0
        continue

    if re.match(r'^TRACK \d+ —', text):
        continue

    m = re.match(r'^Flashcard Set ([ABC])$', text)
    if m and current_module:
        current_set = {'letter': m.group(1), 'cards': []}
        current_module['sets'].append(current_set)
        current_quiz = None
        card_counter = 0
        continue

    m = re.match(r'^Micro-Quiz (\d+) \(3 questions\)$', text)
    if m and current_module:
        current_quiz = {'number': int(m.group(1)), 'questions': []}
        current_module['quizzes'].append(current_quiz)
        current_set = None
        continue

    # Questions: "Prompt → Answer" (number may or may not be in run text)
    if current_quiz and ' → ' in text:
        m = re.match(r'^(.+?)\s+→\s+(.+)$', text)
        if m:
            prompt, answer = m.group(1).strip(), m.group(2).strip()
            kind = 'truefalse' if answer.lower() in ('true', 'false') else 'mcq'
            current_quiz['questions'].append({
                'number': len(current_quiz['questions']) + 1,
                'prompt': prompt,
                'kind': kind,
                'options': ['True', 'False'] if kind == 'truefalse' else [answer],
                'correct': {'answer': answer.lower() == 'true'} if kind == 'truefalse' else {'answer': 0},
            })
            continue

    # Cards: 2 runs, run 0 = term, run 1+ = body
    if not current_set:
        continue
    runs = [r.text for r in para.runs if r.text]
    if not runs:
        continue
    first_run = runs[0].strip()
    if not first_run:
        continue
    card_counter += 1
    current_set['cards'].append({
        'number': card_counter,
        'term': first_run,
        'back': ' '.join(r.strip() for r in runs[1:] if r.strip()),
    })

# Verify
for m in modules[:1]:
    for s in m['sets'][:1]:
        for c in s['cards'][:5]:
            print(f"M{m['number']} {s['letter']} #{c['number']}: {c['term']!r} → {c['back'][:50]!r}")
```

Expected output for the education flashcards docx:

```
M1 A #1: 'What is Forex?' → 'The global market where currencies are traded agai'
M1 A #2: 'Currency pair' → 'Two currencies quoted against each other (e.g. EUR/USD). Fir'
M1 A #3: 'Major pairs' → 'Most liquid pairs that always include the US Dollar (EUR/USD'
M1 A #4: 'Minor vs Exotic' → 'Minors = no USD. Exotics = major + emerging-market currency '
```

If the first card's term is "What is Forex? The global market..." instead, the run split is wrong — re-inspect with the snippet above to see what runs are actually present.
